# /plan - 구현 계획 수립

## 역할

기능 구현 전, 코드를 작성하지 않고 계획만 수립한다.
사용자 승인 없이 코드를 수정하거나 생성하면 안 된다.

## 입력

`$ARGUMENTS` - 구현할 기능 또는 수정할 문제 설명

## 실행 순서

### 1. 컨텍스트 파악

- `AGENTS.md`를 읽어 프로젝트 규칙과 절대 금지 사항을 확인한다.
- 요청과 관련된 기존 파일을 확인한다.
  - 라우팅: `src/App.tsx`, `src/pages/`
  - API: `src/api/`, `src/api/types.ts`
  - 공용 UI: `src/components/`
  - 도메인 기능: `src/features/`
  - 타입/상수/유틸: `src/types/`, `src/constants/`, `src/utils/`
- 기존 UI, 상태 관리, API 호출 패턴을 먼저 확인한다.

### 2. 계획 작성

다음 항목을 포함한다.

- 변경/생성 파일 목록: 경로, 변경 유형, 변경 이유
- 구현 순서: 타입/API/상태/UI/라우팅 순서 고려
- UI 영향: 반응형, 로딩/빈 상태/에러 상태, 관리자/사용자 영역 구분
- API 영향: 요청/응답 타입, 인증 토큰, 환경 변수, 백엔드 의존성
- 테스트 전략: `npm run lint`, `npm run build`, 필요한 수동 확인 화면
- 리스크: 인증, 결제/주문, 신청/관리자 기능, 배포 환경 변수 영향

### 3. 계획 저장

계획을 `.ai-workspace/plan.md` 파일에 저장한다.

파일 상단에 기준점을 기록한다:

```text
> 작성: <날짜> · 브랜치: <현재 브랜치> · 기준 HEAD: <git rev-parse --short HEAD>
```

### 4. 사용자 보고 및 승인 대기

계획 전문을 사용자에게 보여주고 다음을 명시한다.

```text
승인하시면 /impl로 구현을 시작합니다.
```

승인 전까지 코드 수정은 금지한다.

## 주의사항

- 추측 금지. 불확실한 API, 환경 변수, UX 요구사항은 "확인 필요"로 표시한다.
- 작은 문구 수정이나 단순 스타일 수정은 계획을 짧게 작성한다.
- 인증, 주문, 신청, 관리자 기능을 건드리는 경우 영향 범위와 검증 방법을 구체적으로 적는다.
