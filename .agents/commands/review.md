# /review - 변경사항 셀프 리뷰

## 역할

구현된 변경사항을 `AGENTS.md` 기준으로 셀프 리뷰한다.
FAIL 항목은 수정안을 제시하고 사용자 승인을 받는다.

## 실행 순서

### 1. 변경사항 파악

브랜치에서 이미 커밋한 변경까지 포함해 리뷰한다 — 미커밋 diff만 보면 커밋 후 실행 시 리뷰가 빈다.

```bash
git fetch origin main
git diff origin/main...HEAD   # 브랜치의 커밋된 변경 전체
git diff HEAD                 # 아직 커밋하지 않은 변경
```

두 diff 모두 비어있으면 즉시 다음 메시지를 출력하고 종료한다.

```text
리뷰할 변경사항이 없습니다.
```

### 2. 체크리스트 검토

각 항목에 대해 **PASS / FAIL / N/A** 와 근거를 작성한다.

**[범위]**

- 요청 범위 밖 파일이 수정되지 않았는가
- 계획에 없는 리팩토링이나 파일 이동이 없는가
- `node_modules`, `dist` 같은 생성물이 포함되지 않았는가

**[TypeScript / React]**

- 새 `any`가 불필요하게 추가되지 않았는가
- 기존 타입, API 응답 타입, 상수를 재사용했는가
- React state/effect 의존성이 올바른가
- 불필요한 재렌더링이나 중복 상태가 없는가

**[API / 인증]**

- API 호출이 `src/api/` 계층에 위치하는가
- 인증 토큰 처리 방식이 기존 패턴과 일치하는가
- 요청/응답 실패, 로딩, 빈 상태 처리가 필요한 곳에 반영됐는가
- `VITE_` 환경 변수 추가나 변경이 있다면 문서화 필요 여부를 명시했는가

**[UI / UX]**

- 기존 레이아웃, 색상, 간격, 폰트, 반응형 패턴과 일관적인가
- 모바일/데스크톱에서 텍스트나 버튼이 깨지지 않는가
- 관리자 영역과 사용자 영역의 컴포넌트 경계를 지켰는가
- 아이콘은 가능한 경우 `lucide-react`를 사용했는가

**[검증]**

- 변경 범위에 맞는 `npm run lint` 또는 `npm run build`를 실행했는가
- 실행하지 않았다면 사유가 합리적인가
- 수동 확인이 필요한 화면이나 플로우가 명시됐는가

**[보안 / 민감정보]**

- `.env`, 토큰, API 키, 비밀번호 등이 변경사항에 포함되지 않았는가
- 클라이언트 번들에 노출되면 안 되는 값을 `VITE_` 환경 변수로 추가하지 않았는가

### 3. 결과 보고

보고 형식:

```text
[범위] PASS
[TypeScript / React] PASS
[API / 인증] N/A - API 변경 없음
[UI / UX] FAIL - 모바일에서 버튼 텍스트 줄바꿈 확인 필요
[검증] PASS - npm run build 통과
[보안 / 민감정보] PASS

총 FAIL: 1건 - 수정안 검토 후 승인 부탁드립니다.
```

## 주의사항

- 리뷰 중 코드를 직접 수정하지 않는다. 리뷰 -> 승인 -> 수정 순서를 지킨다.
- PASS로 처리하기 애매한 항목은 FAIL 또는 확인 필요로 표시한다.
