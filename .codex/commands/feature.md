# /feature - 큰 기능 작업 워크플로우

## 역할

새 화면, 주요 플로우, API 연동, 관리자 기능처럼 계획-구현-검증-PR 흐름이 필요한 작업을 단계별로 진행한다.
각 단계 사이에 반드시 사용자 확인을 받는다.

작은 문구 수정, 단순 스타일 조정, 파일 하나짜리 버그 수정에는 `/feature`가 과할 수 있다.
그런 경우 필요한 커맨드만 개별적으로 사용한다.

## 입력

`$ARGUMENTS` - 구현할 기능 또는 해결할 문제 설명

## 워크플로우

```text
/plan -> 승인 -> /impl -> lint/build -> 승인 -> /review -> 승인 -> /commit -> push 승인 -> /pr -> PR 생성 승인
```

AI는 구현, 리뷰 수정, 커밋, push, PR 생성, 병합 전에 사용자 승인을 반드시 받는다.

### STEP 1: 계획 수립

`$ARGUMENTS`를 기반으로 `/plan`을 실행한다.
계획을 사용자에게 보여주고 다음 메시지와 함께 대기한다.

```text
계획 수립이 완료됐습니다.
검토 후 "승인"이라고 답하시면 구현을 시작합니다.
수정이 필요하면 수정 내용을 알려주세요.
```

### STEP 2: 구현

사용자가 승인하면 `/impl`을 실행한다.
계획에 없는 변경은 하지 않는다.

### STEP 3: 검증

변경 범위에 따라 실행한다.

```bash
npm run lint
npm run build
```

테스트 성공 시 다음 단계 진행 전 사용자 확인을 받는다.

```text
검증이 완료됐습니다.
승인하시면 /review를 실행합니다.
```

검증 실패 시 최대 3회까지 원인 분석 및 수정 후 재검증한다.
3회 연속 실패하면 중단하고 실패 로그와 함께 보고한다.

### STEP 4: 리뷰

사용자가 승인하면 `/review`를 실행한다.
FAIL 항목이 있다면 수정안을 제시하고 사용자 승인을 받는다.

### STEP 5: 커밋

사용자가 승인하면 `/commit`을 실행한다.
커밋 메시지를 제안하고 승인받은 뒤 커밋한다.
커밋 성공 후 push 여부는 별도로 승인받는다.

### STEP 6: PR 작성 및 생성

커밋 및 필요한 경우 push 완료 후 `/pr`을 실행한다.
PR 설명을 `.ai-workspace/pr.md`에 저장하고 사용자에게 보여준다.
사용자 승인 후 브랜치 push 및 `gh pr create`를 실행한다.

## 전체 진행 상황 표시

각 단계 시작 시 현재 위치를 표시한다.

```text
[feature 워크플로우] STEP 2/6 - 구현 중 (/impl)
```

## 주의사항

- 사용자 확인 없이 단계를 건너뛰거나 자동 진행하지 않는다.
- 어느 단계에서든 사용자가 중단을 요청하면 즉시 중단한다.
- push와 PR 생성은 각각 사용자 승인 후에만 실행한다.
- force push 금지.
- 환경 변수, 인증, 주문, 신청, 관리자 핵심 플로우 변경은 계획 단계에서 리스크와 검증 방법을 명시한다.
