# /impl - 계획 기반 구현

## 역할

`.ai-workspace/plan.md`에 승인된 계획대로만 구현한다.
계획에 없는 변경, 리팩토링, 정리는 하지 않는다.

## 사전 조건

- `.ai-workspace/plan.md` 파일이 존재해야 한다.
- 사용자가 `/plan` 결과를 승인한 상태여야 한다.

## 실행 순서

### 0. 사전 조건 확인

`.ai-workspace/plan.md` 파일이 없으면 즉시 다음 메시지를 출력하고 종료한다.

```text
.ai-workspace/plan.md 파일이 없습니다.
/plan을 먼저 실행하세요.
```

### 1. 계획 확인

- `.ai-workspace/plan.md`를 읽는다.
- `AGENTS.md`를 읽어 프로젝트 규칙을 재확인한다.

### 2. 구현

계획의 작업 순서대로 파일을 생성/수정한다.

준수 사항:

- 기존 컴포넌트, 훅, API 모듈, 타입을 우선 재사용한다.
- API 호출은 `src/api/` 계층에 둔다.
- 재사용 가능한 UI는 `src/components/`, 라우트 단위 화면은 `src/pages/`, 도메인 단위 로직은 `src/features/`에 둔다.
- `any` 추가를 피하고 명시적 타입을 사용한다.
- 아이콘은 가능한 한 `lucide-react`를 사용한다.
- 환경 변수 추가 시 README 또는 PR 설명에 반영할 내용을 메모한다.
- `node_modules`, `dist`는 수정하지 않는다.

### 3. 검증

변경 범위에 따라 실행한다.

```bash
npm run lint
npm run build
```

권장 기준:

- 문서/문구만 수정: 명령 생략 가능, 생략 사유 보고
- TypeScript, API, 라우팅, 인증, 주문, 신청, 관리자 화면 수정: `npm run build` 실행
- UI 변경: 가능하면 브라우저 또는 개발 서버로 주요 화면 확인

### 4. 실패 처리

검증이 실패하면 즉시 원인을 분석하고, 계획 범위 안에서 수정 가능한 경우 수정 후 재검증한다.
계획 밖 변경이 필요하면 사용자에게 보고하고 승인받는다.

### 5. 결과 보고

- 생성/수정한 파일 목록
- 실행한 검증 명령과 결과
- 계획 대비 변경된 사항
- 남은 리스크 또는 수동 확인 필요 사항

## 주의사항

- 커밋/푸시/PR 생성은 각각 해당 커맨드의 사용자 승인 게이트를 거친 경우에만 실행한다.
- 계획에 없는 리팩토링, 스타일 정리, 파일 이동 금지.
- 민감정보 파일은 수정하거나 커밋하지 않는다.
